# 3 分钟 Demo 录制指南

视频文件由提交人录制，本文件只提供镜头脚本。录制前先准备两个学校项目，确保资料和题单已经生成，避免在视频中等待外部 API。

## 0:00–0:25：先给出差异点

打开项目侧栏，在“北大”和“清华”之间切换，然后打开其中一个项目的资料库。

建议旁白：

> 通用 ChatGPT 会记住一段对话，但很难管理不同学校的资料边界。循证保研把每所学校变成独立项目，联网资料、用户上传和三关题单不会串校。

画面必须看到：项目切换、资料数量、自动采集/用户上传分区。

## 0:25–1:05：联网资料到证据

打开一条高质量资料，展示来源类型、摘录、原链接和可信度；再说明系统经过 URL/内容去重、规则预筛和 DeepSeek 二次审查后才允许资料进入题单。

强调：无来源内容不会伪装成历史真题，而会明确显示为“AI 补充”。

## 1:05–1:45：第一关和第二关

进入“机试”，展示题源标签、原题链接和三语言代码编辑器；再切到“面试题单”，展示按高频主题组织的只读题单和版本切换。

建议旁白：

> 系统根据当前院校资料自主决定题量和结构，但每道题都保留来源类别。机试代码只做草稿和一次性复盘，不冒充真实 OJ 判题。

## 1:45–2:25：第三关项目追问

展示脱敏简历、导师或课题组信息，以及按研究方向映射到简历项目的追问。不要在录屏时上传真实简历。

强调：系统只提出可能追问，不生成虚假的项目事实或万能答案。

## 2:25–3:00：迭代、边界与收尾

快速展示 GitHub commit history 或三点项目菜单，说明产品从通用聊天页迭代到三关工作台，并修复了资料筛选和 DeepSeek 结构化输出问题。

收尾句建议：

> 这个产品不是功能最多的 AI 面试官，而是把“我为什么要练这道题”变成可检查、可复用的准备闭环。

## 录制前检查

- 视频总长不超过 3:00，最好控制在 2:40–2:55。
- 浏览器缩放、字体和录屏分辨率保证来源文字可读。
- 关闭通知、密钥弹窗、个人账号和无关标签页。
- 不展示 API Key、真实简历、Cookie、终端环境变量或个人聊天记录。
- 前 30 秒必须出现产品差异，不从安装或登录开始。
- 录完后从头播放一次，确认声音、画面、链接和结尾都完整。
